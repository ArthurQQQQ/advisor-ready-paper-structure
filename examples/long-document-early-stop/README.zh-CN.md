# 冻结证据流程的新题检查

这个案例从「长文档找证据，能不能提前停读」开始，经历题目讨论、基线核查、Quick Paper、逐检查点试验和冻结后的新题检查。

共享证据生成与引文核对流程在三道参与修订的开发题上达到了判定一致。冻结后，新题显示出研究归属、回答目标和限定条件的错误。

## 冻结设置

模型为 OpenRouter 上的 `google/gemini-2.5-flash-lite`，Google AI Studio 路由，温度 0、种子 42、输出上限 1536 token。每 256 个正文 token 加实际篇尾检查一次，每次只开放已读前缀。只有已完整可见的主文段可以引用，未读完的部分只用于发现冲突。

流程核查实际操作证据、输入可用条件、逐论断引文支持，以及冲突双方都支持的窄答案。代码在打开新文档前冻结，运行前后哈希一致。[冻结清单](protocol/freeze-manifest.json)

## 新题结果

预选三篇、六道原题，保留两篇中的三道正文可答题。其余题因问法歧义或表格依赖排除。原预选 240、320、400 中两行越界，按已核实的 281 篇验证集循环映射为 240、39、119，修正发生在查看替代文档前。

逐点参考由独立 Codex 审读原文和前缀后封存，再审读实验模型实际返回的答案与引文。

| 问题 | 模型首次 PASS | 参考首次可答 | 首个充分的模型答案 |
| --- | ---: | ---: | ---: |
| 训练数据怎样标注 | 1280 | 1280 | 1536 |
| 怎样展示 EEG 的判别信息 | 1024 | 2816 | 2816 |
| 五项二分类任务 | 768 | 2048 | 2048 |

45 个检查点中，44 点返回判定，1 点在三次原配置重试后仍生成失败。共有 7 个提前通过点，未出现参考可答却判继续的点。30 个 `PASS` 中有 14 个答案或引文不充分，主要是误用前人多模态研究、把运行时众包预算当成训练标注、漏预处理条件，以及新增无依据的任务比较。

九道正式评估题继续留出，风险校准与正式停读策略比较仍待完成。[逐点结果](results.json) · [标注论文](https://arxiv.org/abs/1608.08188) · [EEG 论文](https://arxiv.org/abs/1904.04358)

## 运行

在执行环境设置 `OPENROUTER_API_KEY`，从仓库根目录运行。

```sh
python3 examples/long-document-early-stop/protocol/run-frozen-citations.py \
  /path/to/prepared-streams /path/to/new-output
```

运行器使用 Python 标准库，需要外部准备的问题、正文阅读流和段落字节位置。详细输入格式、分词配置和恢复行为见[英文说明](README.md#run-with-prepared-streams)。
