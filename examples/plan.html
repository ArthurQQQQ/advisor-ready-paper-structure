Layout cues for passage retrieval

Worked example using fictional data · Source packet

Lead with the paired retrieval pilot.

On the same 24 single-column PDF questions, the layout-aware reranker retrieved the annotated passage 15 times versus 12 for text-only. A comparison across layouts depends on matching the inputs.

Revise first

  1. Name passage retrieval in the abstract and introduction.
  2. Match question IDs, gold passages, and candidate pools before comparing layouts.

Baseline coverage 基线覆盖

  • Paired pilot. The text-only version of the same reranker tests both layout cues together on 24 questions from single-column PDFs with shared candidate pools (E01, E02).
  • Broader comparison. The larger export mixes layouts (E03). Verify that both runs use the same question IDs, gold annotations, and candidate pools before comparing scores by layout (G01).
  • Component claim. If the paper attributes the gain to section headings alone, compare the combined configuration with each single-feature variant using the same pairs, pools, and metric (E04, G03).

Priority checks 优先核对

  1. G01 Rebuild the paired comparison. Join both system runs to the same question IDs, gold annotations, and candidate pools. Record eligible pairs and exclusions by layout before computing scores.
  2. G02 Measure the paired effect. Tabulate both-correct, layout-only, text-only, and neither outcomes. Report denominators and uncertainty alongside the paired difference.
  3. G03 Separate the feature effects. On the fixed pairs and pools, compare the joint configuration with page-position-only and headings-only runs if the paper retains a feature-level claim.

G04 Fix the endpoint in the draft now. Check the claim against E01. This study measures passage retrieval. Keep answer accuracy open.
